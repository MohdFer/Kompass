# 4. Abstract

**KOMPASS** is a mobile application designed to simplify the planning, coordination, communication, attendance management, and safety monitoring of organized tour groups. Existing tour management methods often rely on multiple applications for communication, navigation, attendance, and location sharing, resulting in fragmented workflows, communication delays, and inefficient coordination. KOMPASS addresses these challenges by integrating essential tour management functionalities into a single mobile platform.

The system enables tour organizers and guides to create and manage tours, register participants, maintain itineraries, monitor digital attendance, communicate with participants, broadcast announcements, and share participant locations with appropriate consent. The application also provides map-based location visualization, emergency SOS support, meeting-point management, push notifications, and real-time communication.

The project is developed in two phases. **Phase 1**, implemented as the mini project, focuses on establishing the core tour management platform, including role-based access, tour and participant management, itinerary management, digital attendance, location sharing, messaging, announcements, notifications, and basic emergency support.

**Phase 2** extends the system into a full-fledged and production-oriented platform by introducing a custom hybrid geofencing engine and **BitChat-inspired offline Bluetooth mesh communication**. The geofencing system will support circular and polygonal boundaries using Haversine and Ray Casting algorithms, while the offline communication layer will enable nearby smartphones to exchange and relay messages without depending entirely on internet connectivity.

By combining tour management, real-time communication, location services, geospatial intelligence, safety features, and offline connectivity, KOMPASS aims to provide a smarter, safer, and more organized experience for tour organizers and participants.

# 5. Problem Statement

Managing organized tours using multiple applications and manual processes often results in:

* Inefficient communication between guides and participants
* Inaccurate or time-consuming attendance tracking
* Difficulty monitoring participant locations
* Difficulty identifying missing participants
* Delayed emergency response
* Fragmented tour information
* Increased workload for tour organizers
* Dependence on multiple unrelated applications

Existing solutions generally provide individual services such as messaging, navigation, calling, or location sharing rather than a unified platform specifically designed for tour-group coordination.

Therefore, a centralized mobile application is required to integrate **tour management, attendance, communication, location services, notifications, and safety features** into a single system, with advanced geofencing and offline communication introduced in the second phase.

# 12. Phase 2 — Hybrid Geofencing

KOMPASS will implement a custom geofencing engine capable of handling different geographical boundary types.

## Circular Geofencing

The **Haversine distance algorithm** will be used to calculate the distance between the participant and the center of a circular region.

Suitable for:

* Hotels
* Restaurants
* Bus stops
* Meeting points

## Polygon Geofencing

The **Ray Casting point-in-polygon algorithm** will be used to determine whether a participant is inside an irregular geographical boundary.

Suitable for:

* Parks
* Museums
* Campuses
* Beaches
* Tourist attractions

# 14. Geofencing Optimization

### Bounding Box Filtering

A preliminary bounding-box check can reduce unnecessary polygon calculations.

### Consecutive Exit Validation

Multiple location readings can be used before confirming that a participant has actually left the designated area.

```text
Outside
   ↓
Outside
   ↓
Outside
   ↓
Exit Confirmed
   ↓
Alert
```

This helps reduce false alerts caused by GPS fluctuations.

### Adaptive GPS Polling

The system can dynamically adjust location-update frequency based on movement and proximity to monitored areas, helping reduce unnecessary battery consumption.

# 15. Phase 2 — Offline Mesh Communication

KOMPASS will introduce **BitChat-inspired offline communication** using the Bluetooth capabilities already available in smartphones.

No external Bluetooth hardware modules are required.

The objective is to allow tour participants to communicate even when normal internet connectivity is unavailable or unreliable.

### Example

```text
Participant A
      │
   Bluetooth
      ↓
Participant B
      │
   Bluetooth
      ↓
Participant C
      │
   Bluetooth
      ↓
    Guide
```

A message can potentially be relayed through nearby participant devices until it reaches the intended recipient.

### Planned Features

* Nearby device discovery
* Tour-specific communication groups
* Peer-to-peer messaging
* Multi-hop message relay
* Store-and-forward messaging
* Offline message queue
* Message acknowledgement
* Duplicate-message prevention
* Offline-to-online synchronization
* Secure communication
* Battery optimization

The implementation will be **inspired by the communication approach of BitChat**, while being designed specifically for the controlled requirements of organized tour groups.

# 28. Technical Challenges

### GPS Accuracy

GPS readings may fluctuate because of environmental conditions and signal obstruction.

**Approach:** Accuracy filtering and location validation.

### Battery Consumption

Continuous GPS tracking can consume significant battery.

**Approach:** Adaptive location-update strategies.

### Real-Time Synchronization

Participant information needs to remain synchronized across devices.

**Approach:** Firebase real-time data synchronization.

### WebRTC Connectivity

Direct peer communication may not always be possible.

**Approach:** STUN/TURN-assisted connectivity.

### Geofence False Alerts

GPS drift can result in incorrect boundary detection.

**Approach:** Consecutive validation and accuracy filtering.

### Offline Mesh Communication

Bluetooth communication introduces challenges involving:

* Device discovery
* Limited communication range
* Peer availability
* Multi-hop routing
* Duplicate messages
* Device disconnections
* Message synchronization

**Approach:** Message identifiers, relay mechanisms, queues, acknowledgements and synchronization.

# 32. Conclusion

**KOMPASS** provides a unified approach to organized tour management by integrating tour planning, participant management, attendance, communication, location sharing, notifications, and emergency assistance into a single mobile platform.

**Phase 1** establishes the core tour management and coordination system, providing a functional foundation that can be demonstrated as the mini project.

**Phase 2** builds upon this foundation by introducing the project's more advanced technical components: **custom hybrid geofencing and BitChat-inspired offline Bluetooth mesh communication**, along with enhanced real-time communication, safety mechanisms, synchronization, optimization, and production deployment.

**Phase 3** (see `initial_plan_2.md`) extends the production system with **AI-driven predictive models and smart assistance**, including crowd density prediction, dynamic ETA and routing, lost participant trajectory prediction, a multilingual AI assistant, and health and weather risk alerts — drawing inspiration from IEEE research on smart mobile solutions for large organized groups.

This phased development approach allows KOMPASS to progress from a practical working prototype into a more sophisticated, scalable, and production-oriented tour coordination platform.

> **KOMPASS — One platform to manage the tour, coordinate the group, and keep participants connected and safe.**
